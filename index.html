B / A GOVERNED MISSION

One route.
Explicit boundaries.

Follow the handoffs from identity to settlement. Every stage has a responsibility.

01 / CLERK IDENTITY

Bind the user.

Identity establishes which user and tenant own the mission. The backend carries that boundary into retrieval and journal access.

02 / FASTAPI POLICY GUARD

Check permission before execution.

Entitlements, model access, and rate limits are verified on the server. Frontend state is never the authority for access.

03 / LANGGRAPH PLANNER

Make the route inspectable.

The Planner decomposes a mission into an execution route. Operators can choose required agents and approve the plan.

04 / SPECIALIST AGENTS

Select the right investigators.

Researcher and Analyst responsibilities are explicit. Agent-level tool allowlists constrain the capabilities available to each role.

05 / HYBRID RETRIEVAL

Find meaning and exact matches.

PostgreSQL/pgvector semantic results and BM25 keyword results are fused with Reciprocal Rank Fusion. Queries remain tenant-scoped.

06 / SYNTHESIZER

Build the response from evidence.

The Synthesizer composes the proposed answer from the gathered material. The response still has to pass the challenge layer.

07 / RED TEAM VALIDATOR

Challenge the proposed answer.

Adversarial evaluation looks for unsupported claims, contradictory evidence, weak logic, and hidden assumptions before delivery.

08 / WEBSOCKET STREAM

Expose the execution.

The control plane streams mission steps, agents, model usage, latency, token consumption, approximate cost, and validation state.

09 / TRANSACTIONAL SETTLEMENT

Settle only successful work.

Credits are deducted after successful response generation. Database transactions prevent concurrent requests from overspending the balance.

H / ENGINEERING DECISIONS

The reasons
behind the system.

The most important implementation details are often the decisions that constrain what a system can do.

01Why selective agents?+

Reduce unnecessary model calls and token consumption by running only the agents a mission needs.

02Why success-only credits?+

Users should not pay for failed execution. Deduction happens only after successful response generation.

03Why database transactions?+

Concurrent requests must not overspend the same credit balance. Settlement is a transactional operation.

04Why query-level tenant scoping?+

Isolation cannot depend on frontend behavior. Retrieval and mission-journal queries are scoped to the authenticated Clerk user.

05Why tool allowlists?+

Each agent receives only its permitted tool surface. Least privilege makes the boundary explicit.

06Why separate background workers?+

Durable workloads and scheduled Sentinels are separated from interactive requests. Azure Service Bus supports the infrastructure preparation.

07Why backend entitlements?+

Subscription fulfillment, model access, rate limits, and idempotent webhooks must be verified by the server.

Security, context & operations +

Black Vault & Ghost Mode

Black Vault supports local evidence sanitization and cryptographic manifests before documents enter the workflow. Ghost Mode provides an ephemeral path designed to avoid retaining mission content in persistent conversation history.

Model routing & secure MCP

Provider-aware routing selects OpenAI and Anthropic models according to task complexity, entitlement, latency, and cost requirements. Read-only GitHub and Notion connectors retrieve credentials through a Key Vault boundary rather than raw tokens in application tables.

Product infrastructure

Next.js 16 and TypeScript connect to Python, FastAPI, LangGraph, PostgreSQL, and WebSockets. Docker, Azure Service Bus, and Azure Key Vault support Azure deployment preparation.
