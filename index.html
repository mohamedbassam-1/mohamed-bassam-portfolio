Dark Agent — Governed Multi-Agent AI Mission Control

Don’t chat. Command.

An inspectable, governed AI mission-control platform that coordinates specialized agents, retrieves tenant-isolated evidence, validates outputs adversarially, and streams every execution step through a real-time control plane.

PROJECT STATUSV1.0 Release Candidate · Azure deployment preparation
CATEGORYAgentic AI · Hybrid RAG · Full-Stack SaaS · AI Security
CONTROL PLANEInspectable by design
MISSION BRIEF / 01GOVERNED EXECUTION
THE PROBLEM

Most AI applications are opaque chat wrappers. Users submit a prompt, receive an answer, and have almost no visibility into which tools were used, how evidence was retrieved, what the execution cost was, or whether the final answer was critically validated.

Dark Agent was built to make complex AI execution inspectable, controllable, tenant-isolated, and economically governed.

THE SOLUTION

Dark Agent transforms a single prompt into a governed AI mission. A Planner creates the execution route, specialist agents investigate the task, a Synthesizer constructs the final response, and an adversarial Red Team validator challenges the result before delivery.

Users can select only the agents required for a mission, approve execution plans, watch the workflow stream live, and inspect model usage, latency, retrieval evidence, token consumption, and security controls.

CORE CAPABILITIES

The governed AI mission lifecycle.

Orchestration, retrieval, validation, security, billing, and observability work as one control plane.

01

Governed Agent Swarm

A LangGraph-powered workflow coordinates Planner, Researcher, Analyst, and Synthesizer agents while enforcing explicit execution policies and agent-level tool permissions.

02

Hybrid Retrieval Intelligence

Combines PostgreSQL/pgvector semantic retrieval with BM25 keyword ranking. Reciprocal Rank Fusion merges both result sets so the system can understand natural-language meaning while still locating exact identifiers, technical terms, and code symbols.

03

Adversarial Red Team Validation

A hidden validation agent attacks the proposed final response for hallucinations, logical weaknesses, unsupported assumptions, and contradictory evidence before the answer reaches the user.

04

Live Mission Telemetry

WebSocket streaming exposes execution steps, active agents, selected models, latency, token usage, approximate cost, validation status, and the final answer in real time.

05

Black Vault and Ghost Mode

Black Vault supports local evidence sanitization and cryptographic manifests before documents enter the AI workflow. Ghost Mode provides an ephemeral execution path designed to avoid retaining mission content in persistent conversation history.

06

Production SaaS Control Plane

Clerk authentication, tenant-aware database access, Stripe subscription fulfillment, idempotent webhooks, success-only credit deduction, rate limiting, model entitlements, deterministic audit logs, and scheduled Sentinel jobs are enforced by the backend.

07

Model-Agnostic Routing

Provider-aware routing allows different agents to use models from OpenAI and Anthropic based on task complexity, entitlement, latency, and cost requirements.

08

Secure MCP Integrations

The architecture supports read-only GitHub and Notion connectors with credentials retrieved through a secure Key Vault boundary instead of storing raw access tokens in application tables.

  • Agent selection reduces unnecessary model calls and token consumption.
  • Credit deduction occurs only after successful response generation.
  • Database transactions prevent concurrent requests from overspending credits.
  • Every retrieval and journal query is scoped to the authenticated Clerk user.
  • Tool allowlists enforce least-privilege access for individual agents.
  • Durable background workers and scheduled Sentinels are separated from interactive requests.
  • Subscription entitlements and model access are verified by the backend rather than trusted from frontend state.
